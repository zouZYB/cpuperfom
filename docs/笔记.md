## 缓存一致性协议
### store buffer存在的意义
- 共享（s）时进行写，需要广播所有并且需要收集到Ack回复，延迟很高
- store buffer是先将广播存起来，需要时再一起广播

### memory order
- x86/x86-64的load-load,load-store,store-store是严格按照顺序的（TSO）
- arm都是不要求的
- release，作用与写，前面的读写不能往后挪。也就是保证了屏障前的load-store,store-store的顺序
- acquire，作用于读，后面的读写不能往前挪。也就是保证了屏障后的load-load和load-
- 独立屏障--->std::atomic_thread_fence，一次管多个的情况使用，arm架构可以减少指令
```c++
a = 1; b = 2; c = 3;
std::atomic_thread_fence(std::memory_order_release);  // 一条门管三个写
pa.store(&a, relaxed); pb.store(&b, relaxed); pc.store(&c, relaxed);
```
- std::atomic_signal_fence,编译器屏障，仅仅对编译器生效，不生成cpu指令
- std::memory_order_relaxed，啥也不管
- std::memory_order_release,前面的读写不能往后挪。
- std::memory_order_acquire,后面的不准往前挪
- std::memory_order_acq_rel, 包含std::memory_order_release和std::memory_order_acquire
- std::memory_order_seq_cst，全顺序


### mutex也会有内存屏障
- mutex.lock()，acquire,进入临界区，后面的读取不能往前挪
- mutex.unlock(), release, 前面的不允许往后挪。
- 两者结合就可以保证lock和unlock之间的指令不可能不在临界区内
