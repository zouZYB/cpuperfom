# 分支预测实验场：结果与结论

> 数据来源：`build/bench.json`（224 个场景 × 3 次重复，取中位数）。
> 原始表格：`scripts/report.ps1`；分组分析：`scripts/analyze.py`。

## 0. 测试环境

| 项 | 值 |
|---|---|
| CPU | AMD Ryzen 7 7800X3D（Zen 4，16 线程），Google Benchmark 报告 4200 MHz |
| 缓存 | L1D 32 KiB × 8，L2 1024 KiB × 8，L3 96 MiB |
| OS | Windows 10/11 x64 |
| 编译器 | MinGW-GCC 16.1（`-O3`，关闭自动向量化） |
| CMake | 3.30 |
| 测量 | Google Benchmark，`--benchmark_min_time=0.05s --benchmark_repetitions=3` |

> 双工具链验证：MinGW-GCC 与 **VS2022 + ClangCL**（`build-vs2022/fzyc.sln`）都构建通过，
> 两套产物各跑 21,137 条正确性断言全过；`scripts/check_branches.ps1` 对两套产物的
> 静态检查结论一致（分支版 `cmov=0`、CMOV 版 `cmov>0`）。本文性能数字取自 GCC 构建。

**测量方法要点**（详见 README 第 4 节）：每用例 64K 元素；8 组不同 seed 的输入轮转，
避免预测器把"重复出现的分支序列"记住；`FZ_BARRIER()` 采用"带唯一立即数的空 asm"，
防止编译器把分支 if-convert 成 CMOV；所有内核关闭自动向量化。
`cycle/el` = ns/元素 × 标称 4.2 GHz，仅用于同机对比。

## 1. 结论摘要

1. **分支方向可预测时几乎免费**：可预测分支 0.38–0.45 ns/元素（~1.6–1.9 周期），
   与"没有分支的算术版本"（0.50–0.52 ns/元素）持平甚至更快。
2. **方向随机时一次分支约 10–12 个周期**：`pattern_sum` 从 1.89 → 13.54 cycle/元素，
   增量 11.6 周期/元素，对应"约 50% 误预测 × ~15 周期 + 基础开销"。
3. **数据顺序就是可预测性**：同一段 `if (x >= 128)`，随机数据 1.810 ns/元素，
   升序数据 0.438 ns/元素，差 4.7 倍；1M 元素时排序版仍是 0.43 ns/元素
   （分支预测与缓存效应可以叠加，但主因仍是预测器）。
4. **预测器能记住的周期长度有限**：周期 ≤256 的分支序列基本可学（0.45–0.51 ns/元素），
   512–4096 开始退化（0.62–0.74），8192 以上迅速接近随机水平（1.13 → 2.83 → 3.22）。
   本机的大致容量悬崖在 **1K–8K 位** 之间。
5. **间接分支的目标预测比方向预测更脆**：8 路 `switch` 顺序目标 1.38 ns/元素，
   随机目标 5.29 ns/元素；64 路顺序目标也退化到 5.12（目标过多）。
6. **无分支改写在"高误预测 + 廉价操作"时收益最大**：随机分支求和 1.81 → 掩码版 0.51
   （3.5 倍）；`mapToBucket` 6 分支链 5.21 → 查表 0.38（13.7 倍）。
   但当操作本身很贵或分支本来就便宜时，CMOV 反而更慢（`max_cmov` 0.82 vs 分支 0.43）。
7. **likely/unlikely 提示在本机没有可测收益**（0.88–0.98 ns/元素，差异在噪声内）；
   Clang 的 `__builtin_unpredictable` 会转 CMOV，90% 偏斜下 0.88 → 0.51。

## 2. 数据相关条件分支（`data` 组，60 例子，n=64K）

### 2.1 求和：`if (x >= 128) sum += x; else sum -= x;`

| 数据顺序 | 分支版 ns/el | cycle/el | 掩码版 ns/el | 相对最佳分支 |
|---|---:|---:|---:|---:|
| 全真 (all_true) | 0.386 | 1.62 | 0.516 | 1.00x |
| 交替 (alternating) | 0.392 | 1.65 | 0.506 | 1.02x |
| 块 4 | 0.394 | 1.65 | 0.523 | 1.02x |
| 块 32 | 0.405 | 1.70 | 0.511 | 1.05x |
| 升序 (sorted_asc) | 0.438 | 1.84 | 0.514 | 1.13x |
| 降序 (sorted_desc) | 0.441 | 1.85 | 0.509 | 1.14x |
| 块 64 | 0.502 | 2.11 | 0.513 | 1.30x |
| **随机 (random)** | **1.810** | **7.60** | **0.514** | **4.69x** |
| 随机，n=1M | 1.846 | 7.75 | — | 4.78x |
| 升序，n=1M | 0.432 | 1.81 | — | 1.12x |

随机数据下"分支版 vs 掩码版"= **3.5 倍**；数据一排序，分支版反而回到与掩码版同一水平。
这是"用排序/分块把不可预测变可预测"最直观的证据。

### 2.2 其他内核

| 内核 | 可预测数据 | 随机数据 | 说明 |
|---|---:|---:|---|
| `count_if_branch` | 0.317 (all_true) | 1.748 | 5.5 倍，`count_if_cmov` 恒为 ~0.42 |
| `abs_if_branch` | 0.334 (全正) | 3.175 | 9.5 倍；`abs_cmov` 恒为 ~0.47 |
| `clamp_if_branch` | 0.480 (交替) | 4.142 | 8.5 倍（每次两个数据相关分支）；`clamp_cmov` 恒为 ~0.51 |
| `max_if_branch` | 0.443 | 0.432 | **分支几乎免费**：随机数据下"更新最大值"很少发生，方向极度偏斜 |
| `max_cmov` | 0.834 | 0.824 | 掩码求最大值（`d>>31` 两条掩码链）固定成本更高，**比分支版慢 1.9 倍** |

`max` 是反例：**分支贵不贵取决于误预测率，而不是"有没有分支"**。偏斜分支 + 廉价更新，
保留分支反而更快；盲目 CMOV 化会做多余的无分支计算。

### 2.3 条件存储（`store` 组）

| 版本 | 交替 | 升序 | 随机 |
|---|---:|---:|---:|
| 分支 `dst[i] = x >= 128 ? x : 0` | 0.576 | 0.599 | 2.013 |
| 掩码版 | 0.499 | 0.506 | 0.507 |

## 3. 分支方向模式与预测器容量（`pattern` 组）

`pattern_sum`：`b1[i]` 决定 `sum += v[i]` 还是 `sum -= v[i]`，n=64K。
周期模式由"随机基序列整段重复"构成（不是块状半周期，否则任何周期都能被短 history 学会）。

| 模式 | ns/el | cycle/el | 相对 all_true |
|---|---:|---:|---:|
| 全真 | 0.450 | 1.89 | 1.00x |
| 交替（周期 2） | 0.456 | 1.91 | 1.01x |
| 周期 3 / 4 / 5 / 7 / 8 | 0.451–0.452 | 1.89–1.90 | ~1.00x |
| 周期 16 / 32 / 64 / 128 | 0.474–0.483 | 1.99–2.03 | 1.05–1.07x |
| 周期 256 | 0.513 | 2.15 | 1.14x |
| 周期 512 | 0.618 | 2.60 | 1.37x |
| 周期 1024 | 0.701 | 2.95 | 1.56x |
| 周期 2048 | 0.734 | 3.08 | 1.63x |
| 周期 4096 | 0.744 | 3.13 | 1.65x |
| 周期 8192 | 1.134 | 4.76 | 2.52x |
| 周期 16384 | 2.175 | 9.14 | 4.83x |
| 周期 32768 | 2.826 | 11.87 | 6.28x |
| 游程 3 / 8 / 32 | 0.454 / 0.511 / 0.524 | 1.91 / 2.15 / 2.20 | 1.01–1.16x |
| **随机** | **3.223** | **13.54** | **7.16x** |
| 相位切换（前半全真，后半随机） | 1.836 | 7.71 | 4.08x |

**容量悬崖在 1K–8K 位之间**：≤256 位的历史几乎完全可学；1024–4096 位要靠更多
表项、误预测上升；8192 以上迅速退化为随机。相位切换约等于"一半可预测 + 一半随机"
的算术平均（(1.89+13.54)/2 ≈ 7.7 周期，实测 7.71），说明预测器状态切换几乎即时生效。

## 4. 相关分支（`corr` 组）

`nested_corr`：`if (b1[i]) { if (b2[i]) ... }`，b2 与 b1 的关系由数据决定。n=64K。

| 内外层关系 | ns/el | cycle/el |
|---|---:|---:|
| 完全相关 `b2 = b1` | 3.096 | 13.00 |
| 反相关 `b2 = !b1` | 3.183 | 13.37 |
| 跨迭代相关 `b2[i] = b1[i]^b1[i-1]` | 3.116 | 13.09 |
| 独立随机 | 4.216 | 17.71 |
| 外层周期 4 + 独立内层 | 2.048 | 8.60 |
| 外层交替 + 独立内层 | 1.828 | 7.68 |

内外层相关时，第二个分支的"条件结果"可由全局历史推出（TAGE 领域），
比独立随机少 4.7 周期/元素（1.36 倍）；外层可预测时，内层即使独立也只付 ~7.7 周期的
"单分支随机"成本。

## 5. 分支密度（`density` 组）

每元素 N 个互不相同的分支：

| 每元素分支数 | 可预测（交替）ns/el | 随机 ns/el | 随机/可预测 |
|---:|---:|---:|---:|
| 1 | 0.811 | 3.725 | 4.6x |
| 2 | 1.199 | 4.044 | 3.4x |
| 3 | 1.596 | 4.381 | 2.7x |
| 4 | 2.013 | 4.876 | 2.4x |
| 8 | 3.586 | 6.251 | 1.7x |

可预测时成本随分支数近似线性（每个分支 ~0.4 ns），随机时每元素最多约 2 个有效
误预测被"合并"进流水线（8 个随机分支只比 1 个慢 1.7 倍，而不是 8 倍）——
误预测之间可部分重叠。

## 6. 间接分支与目标预测（`indirect` 组）

### 6.1 `switch`（跳转表，编译器生成 `jmp *%reg`）

| 路数 | 顺序目标 | 随机目标 | 固定目标 |
|---:|---:|---:|---:|
| 2 | 0.427 | 0.427 | 0.421 |
| 4 | 0.392 | 2.764 | 0.430 |
| 8 | 1.381 | 5.293 | 0.820 |
| 16 | 2.815 | 5.654 | 0.443 |
| 64 | 5.119 | 5.826 | 0.445 |

- 只有 2 个目标时，顺序/随机都能被"记住"（0.43）；
- 8 路以上开始出现目标预测代价，64 路顺序目标也退化到 5.1 ns（BTB 装不下/学不会这么长的目标序列）；
- 固定目标最便宜（0.42–0.45）。

### 6.2 函数指针 / if-else 链 / 虚函数

| 形式 | 最优 | 最差 |
|---|---:|---:|
| `callptr`（函数指针） | 1.543（2 路顺序） | 6.514（8 路随机） |
| `ifchain_ways`（if-else 链） | 0.266（2 路顺序） | 5.806（8 路随机） |
| `virtual_call`（虚函数） | 1.245（单目标） | 8.620（2 路 **顺序**） |

虚函数的结果反直觉：**交替目标的顺序模式反而最慢（8.6 ns/元素），随机 4 目标 6.98**。
两者 CV 都在 0.3–1.6%，可复现，不是测量噪声；本机没有 PMU 计数器，无法进一步定位到
具体预测器结构（可能与间接调用目标预测器对"严格交替"的处理有关）。这条记录保留下来
作为"微架构行为需要实测、不能只靠直觉"的例子。

## 7. 循环与调用/返回（`loop` / `call` 组）

### 7.1 内层循环次数（`inner_trip`）

> 注意：为阻止编译器把内层循环折叠成乘法，循环体里每次迭代有一次**不可内联调用**
> （~4 周期/次）。所以绝对值偏高；重点看"恒定/交替/随机"之间的**差值**。

| 循环次数 | 恒定 ns/el | 交替 ns/el | 随机 ns/el |
|---:|---:|---:|---:|
| 1 | 1.227 | 5.246 | 1.227 |
| 2 | 2.259 | 6.364 | 3.517 |
| 4 | 4.362 | 8.304 | 5.276 |
| 8 | 8.400 | 12.451 | 7.663 |
| 16 | 16.769 | 20.804 | 11.855 |

- 恒定次数：循环预测器（loop predictor）几乎零成本，成本只是 ~4.4 周期/次迭代的调用开销；
- 交替 1/9：每次进入循环都要付一次"循环退出"误预测，于是每元素多 ~4 ns（~17 周期）；
- 随机次数：介于两者之间（部分可预测 + 部分误预测）。

### 7.2 展开（`unroll`）和嵌套循环

| 用例 | ns/el | 说明 |
|---|---:|---|
| `unroll=1/2/4/8`，交替分支 | 0.454 → 0.423 → 0.369 → 0.356 | 展开减少循环分支次数，最多 ~1.3 倍 |
| `unroll=1/2/4/8`，随机分支 | 3.196 → 3.088 → 3.113 → 3.087 | 数据分支误预测主导，展开几乎无收益 |
| `nested_loop` 2×4 / 4×4 / 4×16 / 8×8 | 8.6 / 16.8 / 67.2 / 66.5 | 内层循环总次数线性增长 |

### 7.3 调用/返回

| 用例 | ns/el | cycle/el |
|---|---:|---:|
| 直接调用 | 1.042 | 4.38 |
| 8 个调用点轮转（顺序） | 1.230 | 5.17 |
| 8 个调用点轮转（随机） | 1.249 | 5.25 |
| 递归深度 1 / 4 / 8 / 16 | 2.06 / 4.54 / 7.90 / 14.33 | 8.6 / 19.1 / 33.2 / 60.2 |

返回地址栈表现很好：8 个不同调用点顺序/随机几乎无差别；递归成本随深度线性
（~3.6 周期/层），没有出现"返回地址栈溢出"的额外惩罚（深度 ≤16 远小于 RSB 容量）。

## 8. 分支 vs 无分支改写（`branchless` 组）

### 8.1 mapToBucket（PERF 书 10.1 / 10.2）

| 数据 | if-else 链（6 分支） | 查找表 | 算术 `x/10` |
|---|---:|---:|---:|
| 全部落在 [0,50)（bucket50） | 5.210 (21.9 cyc) | **0.381** (1.6 cyc) | **0.400** (1.7 cyc) |
| [0,255] 均匀（wide256） | 2.364 (9.9 cyc) | 1.407 (5.9 cyc) | 1.443 (6.1 cyc) |

分支链在"值域跨桶均匀"时几乎每层都误预测；查表/除法把控制流变成数据流，收益 13.7 倍。

### 8.2 谓词化（computeX/computeY）

| 条件模式 | 分支版（只算一条路径） | 选择版（两条都算 + CMOV） |
|---|---:|---:|
| 交替 | 1.119 | 1.047 |
| 周期 4 | 1.268 | 1.105 |
| 随机 | 3.778 | 3.397 |

两条路径都很便宜时，谓词化小幅胜出；但书中的警告同样成立——如果两条路径昂贵，
"两条都算"的成本可能超过误预测。

## 9. 提示与布局（`hint` 组）

90% 偏斜数据（`skew90`）：`if (x >= 128)`，90% 取真。

| 版本 | ns/el | cycle/el |
|---|---:|---:|
| 无提示 | 0.878 | 3.69 |
| `__builtin_expect(..., 1)`（likely） | 0.982 | 4.13 |
| `__builtin_expect(..., 0)`（unlikely） | 0.917 | 3.85 |
| 热路径写在前面（hot_first） | 0.891 | 3.74 |
| 热路径写在后面（cold_first） | 0.915 | 3.84 |
| `__builtin_unpredictable`（Clang-17+ 才转 CMOV） | **0.513** | 2.15 |

- **likely/unlikely 在本机没有收益**（差异 ≤0.1 ns，且方向不稳定）：现代 CPU 用动态预测器，
  提示只影响代码布局，不改变预测；
- `__builtin_unpredictable` 让编译器改生成 CMOV：90% 偏斜下 0.88 → 0.51（1.7 倍），
  这是"编译器被告知不可预测后主动消除分支"的正面案例；
- `cold_first` 与 `hot_first` 差异在噪声内，说明单一分支的布局影响很小。

## 10. 代码形态验证（`scripts/check_branches.ps1`）

静态统计（GCC 目标文件 / X 条件跳转、CMOV 指令条数）：

| 函数 | 说明 | jcc | cmov |
|---|---|---:|---:|
| `sum_if_branch` | 分支版 | 4 | 0 |
| `sum_if_cmov` | 掩码版 | 4 | 3 |
| `pattern_sum` | 分支版（GCC / ClangCL） | 4 / 4 | 0 / 0 |
| `abs_if_branch` | 分支版 | 4 | 0 |
| `map_ifchain` | 6 分支链 | 9 | 0 |
| `switch_ways` | 跳转表 | 22 | 9（间接跳转/表项选择） |
| `hint_unpredictable` | ClangCL | 5 | 5（被转成 CMOV） |

两个工具链的关键结论一致：**"分支版"里 `cmov=0`，"CMOV 版"里 `cmov>0`**，
说明测量的是预期的代码形态，而不是"编译器自作主张"。

> 踩坑记录：`_ReadWriteBarrier()` 和"空 asm + memory clobber"在 clang-cl 下都会被
> LLVM 提到分支外，`pattern_sum` 仍然被 if-convert 成 CMOV。最终用
> `asm volatile("" :: "i"(__COUNTER__) : "memory")`（每个屏障带唯一立即数）才挡住。

## 11. 测量稳定性

- 224 个用例 × 3 次重复：**CV 中位数 0.54%，P90 1.20%，最大 5.55%**。
- CV 较大的用例集中在 1M 大数组与 `nested_loop`（内存/调度噪声），
  但它们之间的相对差异远大于 CV。
- 同一用例不同 seed（`random` 组 6 个 seed）差异 <2%。

## 13. 已知局限

- 无 PMU：无法给出 `BR_MISP_RETIRED / BR_INST_RETIRED` 的真实误预测率，本文的
  "误预测成本"是从"可预测 vs 随机"的差值反推的。
- 虚函数的"顺序目标反而更慢"未定位到根因（见 6.2），需要性能计数器进一步分析。
- `inner_trip` 的绝对值包含不可内联调用的开销（见 7.1）。
- 数字依赖 CPU/频率/调度；跨机器只可比较趋势，不可比较绝对值。
